# unseen

Find text on a web page that humans cannot see but AI models can read.

When an AI agent browses the web, it reads the page's HTML, not the pixels a person sees. Anyone can hide instructions in that HTML (white text on white, `display:none`, comments, invisible Unicode, `alt` text) and the agent may obey them. This is indirect prompt injection. `unseen` scans a page, reports what is hidden, and can produce a cleaned text version that is safer to hand to a model.

**Live demo:** https://unseen-scan.duckdns.org:9443
(It runs on a small free server with rate limits, so it may be slow or offline. Note the `:9443` port.)

**PyPI:** https://pypi.org/project/unseen/

## What it detects

Six detectors, each reporting a severity (low, medium, high). Findings at the same location are merged, and a hiding trick plus an instruction at the same place is always HIGH.

| Detector | Catches |
|---|---|
| `css_hiding` | `display:none`, `visibility:hidden`, zero opacity, zero font size, off-screen positioning, `text-indent`, clipping, zero-size containers, text colour equal to background, the `hidden` attribute (inline styles and `<style>` blocks) |
| `invisible_unicode` | Zero-width characters, bidirectional controls, Unicode tag characters |
| `html_comments` | Long comments and comments containing instructions |
| `hidden_attrs` | Instructions in `alt`, `title`, `meta`, `noscript`, `aria-hidden` content and hidden form inputs |
| `instruction_patterns` | Phrases aimed at AI models, such as "ignore previous instructions", persona switches, concealment and secret extraction. English plus French, Spanish, German and Turkish |
| `render_diff` | With `--render`: text that a real headless browser does not display, which static analysis can miss |

pip install unseen

## Usage

```
unseen scan <target> [options]
```

`target` is a URL or the path to an HTML file.

| Option | Meaning |
|---|---|
| `--json` | Print results as JSON |
| `--min-severity {low,medium,high}` | Only show findings at or above this level |
| `--fail-on {low,medium,high}` | Exit with code 1 if any finding is at or above this level (default: high) |
| `--sanitize FILE` | Write a cleaned text version of the page, with hidden content removed, to FILE |
| `--render` | Also render the page in a headless browser (needs Playwright) |

Examples:

```
unseen scan https://example.com
unseen scan page.html --min-severity medium
unseen scan https://example.com --render --json
unseen scan page.html --sanitize clean.txt
```

Exit codes: `0` nothing at or above `--fail-on`, `1` risk found, `2` error (including a missing Playwright with `--render`). This makes it usable in CI.

## Web version and API

A small web app lets you paste HTML or scan a URL and shows the findings next to the cleaned text.

```
python -m uvicorn unseen.api:app
```

`POST /scan` takes exactly one of `url` (http or https) or `html` (up to 2,000,000 characters), plus optional `render`, `sanitize` and `min_severity`. `GET /health` returns `{"status": "ok"}`.

## Safety design

A service that fetches arbitrary URLs is a risk in itself, so the hosted version is built defensively:

- **SSRF guard:** only http and https on ports 80 and 443, no embedded credentials, and every resolved address must be publicly routable. Private, loopback, link-local and cloud metadata addresses are refused, including IPv4-mapped IPv6 forms.
- **DNS rebinding protection:** the connection is pinned to the address that was checked, with the original host kept for the Host header and TLS verification. Every redirect is validated again.
- **Limits:** 10 s per request, 15 s in total, 2 MB page cap, at most 5 redirects, proxy environment variables ignored.
- **Rate limits:** 10 scans and 3 browser renders per visitor per minute, one render at a time.
- **Render isolation:** the headless browser runs with all network requests blocked and as a non-root user inside the container.
- **Output safety:** scanned text is shown as plain text, never as HTML.

## Benchmark

`python benchmark.py` runs every fixture in `tests/fixtures` (generated by `python tests/make_fixtures.py`).

| Result | Score |
|---|---|
| Poisoned fixtures detected | 30 / 30 |
| Clean look-alike fixtures flagged | 0 / 17 |

The clean set includes cookie banners, accordions, skip links, screen-reader-only text, closed dropdowns, hidden CSRF fields and noscript fallbacks. The suite has 243 tests with 94% coverage.

Real pages scanned with the CLI (medium and above): Flask, the Python docs, MDN, Hacker News, BBC Good Food, Tailwind, BBC News and The Guardian come out clean, and Wikipedia reports only low-severity notes. Tuning on these sites removed false positives on skip links, closed menus and screen-reader labels.

## Limitations

- The English phrase list is the most complete. Other languages cover only common phrasings.
- External stylesheets are not loaded by the static detector (the `--render` check covers visual hiding).
- A determined attacker can phrase an instruction in a way no list matches. `unseen` reports hidden content, which is the stronger signal, and flags instruction-like text on top of it.
- Some sites block automated fetching (HTTP 403).
- The hosted demo runs a single worker with in-memory rate limits.
